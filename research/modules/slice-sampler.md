# Slice Sampler

## Scope

`slice-sampler` is a dual mono trigger-sliced sampler in the `voice` category. Its reference is the Erica Synths Sample Drum. Each independent player takes a rhythmic trigger, can address one of 32 slices by CV, and can transpose, reverse or loop the selected sound. Local WAV import and live recording both replace the sample in one player. Two original, deterministic factory phrases make a new instance immediately playable. Model the performance behavior in software. Make Noise Morphagene's tape and granular editing metaphor belongs to a different instrument.

## Hardware evidence and decisions

Make Noise's 20 HP Morphagene is the reel-based alternative in the brief. Its stereo reel holds up to 2 minutes 54 seconds and **up to 99** splices. Vari-Speed changes speed and direction, Gene-Size and Slide address grains, and SOS blends live input and existing material. An envelope follower and end-of-splice/gene trigger support patching the process back into a rack. This project follows Sample Drum's independently triggered mono lanes for break and vocal cuts. [Make Noise, Morphagene specifications and manual](https://www.makenoisemusic.com/modules/morphagene/)

The 14 HP hardware has a screen, six push encoders, channel selector, two trigger/audition buttons, two trigger jacks, six assignable CVs, two outputs and microSD. The lower CV3 jack doubles as the recording input. Each channel plays one voice, while both share about five minutes of sample RAM. The manual describes C0–C8 relative transposition, 10 V peak-to-peak audio, configurable CV ranges, and forward or reverse playback with a loop option in each direction. The target WAV is mono PCM16 at 48 kHz. Lower-rate files play at their original speed. Tune at the reference setting preserves the recorded pitch regardless of the note in the file. ## Panel and voltage contract

A 16 HP custom panel titled **SLICE SAMPLER** uses `module-color-six`. Tabs A and B select an editor only. Keep audition, recording state and separate mono outputs legible. The following names use suffix A or B, e.g. `tuneA` and `cv3B`. All defaults apply to both channels.

| Control or indication | Behavior |
|---|---|
| Source | Factory or Local. Factory is the default. Import WAV opens a local file picker. Show the local filename or Capture, its duration, and a readable error for a failed import. “Load local WAV” identifies a Local slot whose PCM is unavailable after reopening a patch. |
| Tune / Level | Tune from −24 to +24 semitones, default 0. Level from 0 to 1, default 0.8. |
| Play mode | Forward one-shot (default), reverse one-shot, forward loop, reverse loop. Loops repeat the selected slice until another trigger or a Stop action. |
| Order | Forward (default), backward, random, address. A dial selects one fixed region in address mode with CV unpatched. The order controls the sequence of region identities. |
| Slice / Count / slicing method | Slice selects 1–32, default 1, clamped to the current region count. Count selects 1–32 equal regions, default 4. Grid (default), Zero and Manual select the partition. |
| Markers | Show starts against a bounded waveform overview. Click/touch or use a labeled position input to set a cursor. Add inserts at the cursor, Move sets the selected interior marker, Remove deletes it. Marker selection and cursor have keyboard equivalents. Enter Manual from Grid/Zero by copying the current interior starts on the first edit. The start at zero and the terminal boundary stay fixed. Announce the slice count and selected marker in text. |
| CV assignments 1, 2, 3 | Each independently selects Off, Pitch, Slice, Level or Reverse. Defaults are Pitch, Slice and Off. Repeated continuous destinations add before clamping. Reverse sources combine as a high gate. The hardware prevents duplicate destinations and offers variable attenuation. The browser uses explicit fixed scaling. |
| Actions and lights | Audition triggers the corresponding voice once. Stop ends looping or one-shot playback with a short release. Record starts capture, pressing it again commits. A filled buffer commits automatically. Use rising-edge actions and a separate runtime recording light so a patch cannot arm a recorder on load. Playback/activity and recording LEDs per channel report values in 0–1. |

| Jack, per channel | Contract and normal |
|---|---|
| `trigA/B` | Trigger input, 0–10 V, normal 0. Fire on rising through 1 V inclusive, once for a held high. A sample-offset edge can retrigger during playback. |
| `cv1A/B`, `cv2A/B`, `cv3A/B` | CV inputs, −5 to +5 V, normal 0. Pitch adds 1 octave per volt. In Address, Slice adds one full index range across 0–5 V to the dial's zero-based position. Saturate at the last bin for 5 V. Level adds V/5 to the dial. Reverse at ≥1 V toggles the panel direction for the next trigger. |
| `recA/B` | Mono audio input, ±5 V, normal 0. Capture only when armed. Silence is a legitimate recording. Finite guard and clip before storing. |
| `outA/B` | Independent mono audio, ±5 V. Idle outputs fill every frame with zero. Full-scale signed PCM maps to roughly ±5 V at unity level. Monitoring can be patched with an external mixer. |

Apply pitch and level continuously. Latch slice, play mode, direction and start/end on each trigger. Changing an addressed voltage while the slice sounds affects the next hit. For N regions the address is clamp(base + floor(clamp(volts, 0, 5) × N / 5), 0, N − 1). A new forward sequence starts at region 1, a backward sequence at N. Random uses a private seeded generator per voice for reproducibility. A sample replacement resets that channel's order cursor. Stop resets its sequence to the first traversal position. Simultaneous manual and jack triggers coalesce.

## DSP and media ownership

1. Store mono signed 16-bit PCM together with its original rate and valid frame length. Use half-open regions [start, end). A signed fractional read head starts at start or end − 1. Step size is sourceRate / engineRate × 2^(clamp(tune / 12 + pitchCV, −4, 4)). Interpolate linearly between adjacent frames inside the region. Wrap overshoot in loops and handle a single-frame region safely. Linear interpolation costs two bounded reads and introduces high-frequency rolloff and possible aliasing at high rates. A band-limited polyphase resampler improves deep transposition at greater cost. Check bright pitched-up hits in a real worklet before extending the rate range. [Julius O. Smith III, Physical Audio Signal Processing, Linear Interpolation as Resampling, 2010](https://www.dsprelated.com/freebooks/pasp/Linear_Interpolation_Resampling.html)
2. Allow a short gain transition at the ends and on hard retriggers, Stop and source replacement. A roughly 1 ms linear ramp or crossfade shrunk for short regions preserves percussion onsets. On retrigger, start from the previous output and converge to the new reading. A loop seam uses the same bounded transition. Linear weights and rail-limited PCM keep the mix within ±5 V. Interpolate inside the active region to avoid bleeding the previous or next hit across a boundary.
3. For N automatic regions select min(N, frames). Grid starts at floor(k × frames / N). Zero mode searches for a sign crossing in a bounded neighborhood around each nominal start (e.g. ±64 frames, also constrained by neighboring boundaries). Choose the nearest crossing, earlier on ties, and retain the grid point when none exists. Manual starts are at most 31 unique sorted interior normalized positions. Map to strictly increasing frame offsets, dropping collisions on very short media. Cache boundaries on sample, count, mode or marker changes. Do not scan a file on a trigger or allocate an array per quantum. Use a bounded overview, e.g. 96 min/max bins computed during import, factory creation or recording, and expose effective starts plus play/record status through bounded telemetry.
4. Generate short, distinct A/B factory phrases deterministically at a fixed source rate. Example A has four equal slots with a swept sine kick, seeded snare noise, a short closed hat and a pitched tom. Example B has a complementary metallic or pitched pattern. Use original synthesis, shared read-only factory arrays per JS realm and no network requests. Disconnected inputs leave both voices idle.
5. On the main thread check file size before reading. Accept bounded little-endian RIFF/WAVE PCM format 1, 16-bit signed, mono or stereo, 8–96 kHz, up to 8,388,608 mono frames per slot (16 MiB of decoded PCM), with a 33 MiB input file bound including stereo samples and metadata. A stereo file is converted to mono with the arithmetic mean of L and R, so exports from the rack's stereo Recorder are usable. Validate RIFF length, chunk bounds, fmt fields, block alignment, complete nonempty data frames and product of frames/channels/bytes. Skip ancillary/unknown chunks including odd padding, allow legal chunk ordering. Unsupported encoding, truncation, zero frames and over-limit files show an error and leave the last playable sample intact. Retain source rate for correct pitch at 44.1, 48 and 96 kHz engine rates. [Microsoft, Resource Interchange File Format, 2021](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-)
6. Reserve at most 16 MiB of committed mono PCM per channel, allocated to actual length. At 48 kHz the two slots together hold about 5 min 50 s. Live capture is capped at 30 seconds per channel. Allocate capture scratch only for a recording, keep the prior committed sample playable, and publish the valid prefix when recording stops or reaches the cap. Include the valid prefix on stop-audio runtime capture. Bound waveform/snap work outside the sample loop and share immutable factory media. Two simultaneous recordings at 96 kHz need at most another 11 MiB of temporary mono PCM.
7. File bytes, names and recorded PCM belong to local runtime state. Persist controls and the small marker arrangement with patch v3. Reopening or copying a patch with Source set to Local requires reloading media; the empty local slot is silent and identified on the panel. Keep the layout associated with its channel so reimporting the same WAV reapplies its cuts. Saving a patch, sharing a URL or rendering an account preview must never send sample contents or filesystem paths. A Factory patch reconstructs exactly from controls and its built-in media. DSP reset silences transports, clears trigger history, scratch recording, sequence/random state, output buffers and lights. Keep committed media and panel settings for replay; module removal drops their ownership.

### Host integration

The renderer passes a stable DSP mirror and onParamChange to custom panels. `RackHost.createRuntimePatchState()` attaches runtime snapshots on startup. `stopAudio()` captures the active DSPs and saves their runtime state. During topology edits the processor reuses live instances and only restores runtime state in `createModule()`. Editing the mirror or posting another topology with a runtimeState field therefore cannot install a new sample in the running player. The recorder's module events travel from the audio thread to the browser; its event drain transfers ownership of returned buffers. [Rack host](../../src/js/app/rack-host.js) · [Worklet engine](../../src/js/audio/worklet-engine.js) · [Worklet processor](../../src/js/audio/worklet/processor.js) · [Renderer](../../src/js/ui/renderer.js) · [Looper runtime hooks](../../src/js/modules/loop/index.js) · [Recorder events](../../src/js/modules/rec/index.js)

Plan one narrowly scoped runtime-media delivery hook. The panel decodes a user-picked file off the render thread, then calls an instance-bound renderer callback. `EurorackApp.renderModule()` forwards it to the host only while its captured moduleState is still the current object, like the existing param callback. When stopped, apply the validated one-channel operation to the latest stopped snapshot (restore the mirror first), capture the resulting runtime state, and show its status. When running, send the operation to the matching live instance on the MessagePort with the engine revision, module ID/type, request ID and owned PCM buffer. The definition validates channel, typed array, valid frame count, rate and bounds before swapping the one slot. The engine resolves success only on acknowledgement and drops/rejects stale replies or stopped-engine requests. Mirror and UI receive bounded metadata; existing stop/start capture hooks preserve the committed media. Keep the other channel's live recording and voice state when applying an update. Transfer a disposable decode buffer or make one deliberate copy if the sender retains PCM. Skip replaying bulk restore state into retained instances on cable-only edits where possible. A failed async decode, obsolete panel or rejected update cannot replace the prior sample; guard overlapping imports per channel or disable its input until completion. A preview lacking the host callback leaves import unavailable.

An alternative is to accept imports only while audio is stopped, merge one slot into the retained runtime state, and restore it using the current creation path on the next start. That avoids a new processor message but interrupts a playing rack to audition a new sound. Prefer the live path for clocked comparison. Encoding audio as patch parameters would put PCM in normal save/share payloads and cause large repeated clones. Sample bytes stay outside that route. ## Implementation observations

The factory phrases use 24 kHz mono PCM with four 200 ms regions each. Player A synthesizes a swept kick, seeded snare, closed hat and tom. Player B uses four decaying bell tones. Both arrays are shared read-only in each JavaScript realm. The 1 ms transition shortens to at most an eighth of a region. Single-frame hits therefore remain audible. Playback interpolation holds the last frame at a region boundary.

Live capture grows in 4,096-frame signed PCM chunks, retaining at most one partially used chunk. Committing a take switches ownership of the chunks and selects Local at the end of the recording. Only the stop-audio snapshot flattens the valid frames into contiguous PCM. The overview uses at most 96 bins and 32 evenly spaced probes per bin, including bin endpoints. This bounds work on file replacement and recording commit. A short isolated transient in a very long file can fall between display probes. Zero snapping always uses the actual PCM around each proposed start. Imported 8–96 kHz WAVs can contain up to 8,388,608 frames. Recordings keep the actual engine rate and are capped at 30 seconds and the same frame limit.

The direct audit ran 79 parameter scenarios on each of the six supported rate/block combinations. Outputs ranged from −3.911 to +3.949 V with finite full blocks, stable buffer identities and zero reset output in every case. Focused fixtures check signed full-scale PCM, exact capture prefixes, trigger offsets, CV addressing, sample-rate conversion and ramp lengths. At 48 kHz the browser imported a 320 Hz tone, recorded it into the other player, then replaced the first player's file with a 640 Hz tone while stopped. The restarted worklet delivered 640 Hz left and 320 Hz right. Host tests also cover recording just before Stop and replacing a patch while a media operation is in flight. [Chromium test](../../tests/e2e/composition-modules.spec.js) · [Host tests](../../tests/app/sampler-runtime.test.js)

The isolated module checks passed 20 DSP, WAV and panel tests. They included a real cross-realm Int16Array and rejected unsigned, spoofed and DataView replacements. Headless Chromium layout measurements found every visible control and jack inside the 288 × 360 px factory panel and the 288 × 380 px standard panel. Guide table checks matched all 28 controls, 10 inputs and two outputs.
